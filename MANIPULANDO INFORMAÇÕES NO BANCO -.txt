MANIPULANDO INFORMAÇÕES NO BANCO - DML

São operações de manutenção de um banco de dados:

Inclusão ou inserção de dados em uma tabela.
Alteração ou atualização de dados em uma tabela.
Exclusão ou deleção de dados em uma tabela.

Populamos um banco de dados utilizando as instruções DML, 
que são: INSERT, UPDATE e DELETE.


INSERT:

INSERT INTO  <nome-tabela> 
	[(<nome-coluna>, [<nome-coluna>],...)]
VALUES 
	(<conteúdo>, [<conteúdo>], ...);


UPDATE:

UPDATE <nome-tabela>
SET <nome-coluna> = <novo conteúdo para o campo>         
  [,<nome-coluna> = <novo conteúdo para o campo>]
[WHERE <condição>]


DELETE:

DELETE FROM  <nome-tabela>
	[WHERE <condição>]



====================

É POSSÍVEL REALIZAR UMA UPDATE DE UMA TABELA, UTILIZANDO COMO INFORMAÇÃO O RESULTADO DE UMA CONSULTA SELECT REALIZADA EM OUTRA TABELA.

EXEMPLO: ALTERAMOS A ATBELA SIP PROJETO PUXANDO OS DADOS DA TABELA SIP COPY PROJETO FIN

UPDATE T_SIP_PROJETO
   SET DT_TERMINO = 
       (SELECT DT_TERMINO FROM T_SIP_COPY_PROJETO_FIN WHERE CD_PROJETO = 1)
WHERE DT_TERMINO IS NULL;

CAP 9 - COMANDOS DRS(LINGUAGEM DE RECUPERAÇÃO DE DADOS) - JOIN 

A consulta de dados é uma pesquisa realizada no banco de dados, cujo propósito é recuperar as linhas (registros) que atendem às condições pré-estabelecidas.

A instrução utilizada para a realização das consultas é o SELECT, que faz parte da categoria de operações DML (Data Manipulation Language)

O comando SELECT a partir de junções (JOIN) nos permite a pesquisa em múltiplas tabelas. Esta pesquisa é necessária, quando precisamos recuperar dados que estão distribuídos em várias tabelas.

A operação JUNÇÃO (JOIN) é usada para combinar registros e linhas relacionados dentro de um único registro/linha. Esta operação nos permite processar os relacionamentos entre os registros (linhas) das tabelas.

O critério de relacionamento estabelecido pode ser baseado em junções idênticas (equijoins), não idênticas (non-equijoins), internas (inner join), externas (left join, right join ou full join) ou autojunções (self-join).

----------------

Há dois tipos de condições de join, baseadas no operador utilizado:

EQUIJOINS:
Utilizam o operador de igualdade ( = ). São consideradas como consequência de um modelo relacional, ou seja, espelham a relação dos dados representados em um modelo E-R. São as relações em que temos a presença das chaves primária e estrangeira.

NON-EQUIJOINS:
Utilizam um operador que não é o de igualdade, como <, >, BETWEEN etc. São consideradas como junções atípicas, em que não há a presença de chave primária e nem mesmo chaves estrangeiras. Os relacionamentos são feitos por meio de colunas, normalmente não chaves primárias e nem únicas, mas que possuem algum tipo de relação associada à necessidade de negócio, para que possamos expressar a junção.

--------------

Há três tipos diferentes de JOINS:

Joins Internas: Retornam um registro (linha) somente quando as colunas da junção tiverem valores que satisfaçam a condição da junção.

Joins Externas: Retornam um registro (linha) mesmo quando uma das colunas na condição de junção tiver um valor nulo.

Autojoins: Retornam registros (linha), possuem valores associados na mesma tabela.

---------------------

Comando SELECT utilizando junções:

Para recuperarmos os dados das tabelas de um banco de dados, utilizamos o comando SELECT, que é um comando dentro da divisão DRS/DQL da linguagem SQL

Sintaxe básica do comando SELECT utilizando junções:

SELECT tabela1.coluna, tabela2.coluna
FROM tabela1
	[CROSS JOIN tabela2] |
	[NATURAL JOIN tabela2] |
	[JOIN tabela2 USING (nome_coluna)] |
	[JOIN tabela2
	ON(tabela1.nome_coluna = tabela2.nome_coluna)] |
	[LEFT|RIGHT|FULL OUTER JOIN tabela2
	ON (tabela1.nome_coluna = tabela2.nome_coluna)];

CROSS JOIN - JUNÇÃO CRUZADA

SELECT * FROM T_DEPARTAMENTO CROSS JOIN T_FUNCIONARIO;

Aqui é como se cada linha de departamento se associasse a todas as linhas da tabela funcionário
Nem sempre essa junção é uma verdade. Exemplo 5 dep e 15 funcionários ele associa cada departamento com todos os 15 funcionários, somando em 75 linhas na consulta.

INNER JOIN - JUNÇÃO INTERNA

QUANDO JUNTO DUAS OU MAIS TABELAS MAS APENAS AS LINHAS QUE SE ASSOCIAM. É BASEADA NOS RELACIONAMENTOS QUE TEMOS ENTRE AS TABELAS. REFLETE AS LINHAS QUE SE ASSOCIAM DENTRO DE UM RELACIONAMENTO ENTRE DUAS OU MAIS TABELAS.
SEMPRE COMPARA ***CHAVE PRIMARIA E CHAVE ESTRANGEIRA***. UTILIZAMOS APELIDOS PARA FACILITAR A IDENTIFICAÇÃO DO CÓDIGO.TRÁS EXATAMENTE OS ELEMENTOS QUE ESTÃO RELACIONADOS.
NESTE EXEMPLO VAMOS RECUPERAR OS DADOS DAS COLUNAS MATRICULA, CÓDIGO DEPARTAMENTO, NOME DEPARTAMENTO, NOME FUNCIONARIO,E ORDENAR TUDO POR NOME DO DEPARTAMENTO(ORDER BY).

SELECT F.NR_MATRICULA, F.CD_DEPTO,
       D.NM_DEPTO, F.NM_FUNCIONARIO
  FROM T_DEDARTAMENTO D INNER JOIN T_FUNCIONARIO F
       ON ( D.CD_DEPTO = F.CD_DEPTO )
ORDER BY D.NM_DEPTO;



EXEMPLO COM A CLAUSULA ***USING***

USAMOS QUANDO O NOME DA PK E FK SÃO OS MESMOS POREM O TIPO DE DADOS É DIFERENTE.
COM ESSA CAUSULA NÃO UTILIZAMOS QUALIFICADOR(APELIDO DA TABELA) NEM NO SELECT E NEM NA CLAUSULA, POIS O NOME DO CAMPO É IGUAL NAS DUAS TABELAS. SE USAR QUALIFICADOR VAI DAR ERRO NESSA SITUAÇÃO. AQUI VAMOS COMPARAR CD_DEPTO.

SELECT F.NR_MATRICULA, CD_DEPTO,
       D.NM_DEPTO, F.NM_FUNCIONARIO
  FROM T_DEDARTAMENTO D INNER JOIN T_FUNCIONARIO F
       USING ( CD_DEPTO )
ORDER BY D.NM_DEPTO;



EXEMPLO CONSULTANDO 3 TABELAS:
VAMOS JUNTAR AS TABELAS IMPLANTACAO, PROJETO E FUNCIONARIO. QUANDO UTILIZAMOS ESSA JUNÇÃO PRECISAMOS TER EM MENTE OS RELACIONAMENTOS. PRECISAMOS CONCIDERAR OS PARES DE ENTIDADES. VAMOS ELABORANDO DE 2 EM 2 TABELAS.
A CADA 'ON' DUAS TABELAS. SEMPRE SEGUIR A ORDEM DAS RELAÇÕES.
AQUI NO EXEMPLO VAMOS RECUPERAR QUAIS PROJETOS ESTÃO EM IMPLANTAÇÃO E QUAIS FUNCIONARIOS ESTÃO TRABALHANDO NESSES PROJETOS.

SELECT F.NR_MATRICULA, F.NM_FUNCIONARIO,
       P.NM_PROJETO,
       I.DT_ENTRADA, I.DT_SAIDA
  FROM T_PROJETO P INNER JOIN T_IMPLANTACAO I
       ON ( P.CD_PROJETO = I.CD_PROJETO )
       INNER JOIN T_FUNCIONARIO F 
       ON ( F.NR_MATRICULA = I.NR_MATRICULA )
ORDER BY F.NM_FUNCIONARIO;
